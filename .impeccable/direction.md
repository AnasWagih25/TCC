# Confectionery shop window

User request: redesign the entire Cookie Concept website using Impeccable and local project design skills. Simple navigation, rich interaction, restrained animation, customer reviews with optional order photos. User explicitly delegated the full redesign direction.

Mode: Persuade on the storefront/story; Operate on menu, ordering and staff portal.

Grounded directions considered: café menu, recipe journal, gift packaging, bakery counter, independent food magazine, celebration stationery, confectionery shop window. The direction seed assigned the seventh candidate; its generous product presentation, a warm paper ground, recognizable Ahsing lettering and clear menu path govern the implementation. The competing teletext, ebru, forging, alphabet-storm, cartoon and loteria systems lose product clarity for this bakery. Their useful disciplines are translated as findable categories, deliberate composition, clear selection feedback, expressive readable lettering, playful restraint and comprehensible box progress.

FIRST VIEWPORT: chocolate Ahsing headline “A good idea. A great cookie.” on warm cream; the actual configured hero photo dominates a shop-window arch to the right; direct menu action and plain product description on the left; mobile brings the photograph beneath the heading and keeps ordering within the first screen. No invented ratings, customer counts or testimonials.

Signature interaction: the “love at first bite” cookie seal reveals the existing QUIRK promotion inline, with clipboard feedback. Photo arrival uses a short transform/opacity entrance rather than a continuous rotation. Scroll reveals run once using IntersectionObserver and WAAPI. Reduced motion removes animation. Products retain image galleries, sizes, customizations and box configuration. Customer photo previews and the native dialog photo viewer support the review experience.

Cross-surface grammar: paper/espresso/blush, Ahsing headings with Outfit interface typography, calm tonal surfaces, compact rounded images, pill actions, generous space between sections and consistent footer/navigation. Forms remain ordinary labeled controls.

Build path for this implementation: code-led, using existing real bakery imagery; no generated comp has been approved and no standing workflow preference is written. No assets were generated.

Honest limitations: Firebase rules/claims need deployment configuration before production moderation is trusted. No cloud writes, real orders, messages or fake reviews are performed during local checks. Existing legacy lint debt is documented separately. Published-review views currently load at most 200 entries. Images detached from reviews remain in Storage.
